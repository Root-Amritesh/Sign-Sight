# SignSight SOC Operations Glossary

This document establishes the official, unambiguous terminology for SignSight. All UI components, API contracts, telemetry views, and user-facing notifications must strictly adhere to these definitions.

---

## 1. Core Objects & Records

| Term | Definition | Context / Rule |
|---|---|---|
| **Flow** | A single network telemetry record defined by a 5-tuple (source IP/port, destination IP/port, protocol) plus flow duration, packet counts, and byte volume rates. | Use when referring to raw telemetry or ingested network events. Never call a flow an "incident" or "alert". |
| **Alert** | A network flow flagged by Stage 1 (Isolation Forest) and classified by Stage 2 (LightGBM) that requires human-in-the-loop analyst triage. | Use for any item in the triage queue or threat map. Do not interchange with "event" or "log". |
| **Detection** | The algorithmic conclusion generated by the machine learning pipeline before analyst review. | Reserved for model output (e.g. "Stage 2 multi-class detection"). |
| **Attack Family** | One of the four supervised attack classifications predicted by LightGBM: `DoS` (Denial of Service), `Probe` (Reconnaissance / Port Scan), `R2L` (Remote to Local unauthorized access), or `U2R` (User to Root privilege escalation). | Always capitalize attack families in UI chips and tables. |

---

## 2. Machine Learning Metrics & Pipeline

| Term | Definition | Context / Rule |
|---|---|---|
| **Stage 1 Anomaly Score** | Continuous metric $[0.0, 1.0]$ computed by the unsupervised Isolation Forest. | Scores $> 0.50$ denote statistical deviation from baseline nominal traffic. |
| **Stage 2 Attack Probability** | Supervised softmax probability distribution $[0.0, 1.0]$ across attack families computed by LightGBM. | Highest probability determines the predicted attack family. |
| **Confidence** | Percentage confidence value associated with the top predicted attack family. | Shown as tabular mono percentages (e.g. `94.2%`). |
| **Novel Suspicious** | A flow exhibiting an elevated Stage 1 Anomaly Score ($> 0.70$) whose Stage 2 attack probability is diffuse or unclassified. | Represents unprofiled zero-day behavior evading traditional signatures. |
| **Decision Threshold** | The configurable anomaly score cutoff (default `0.50`) above which flows are escalated to the Stage 2 classifier. | Configured via `/app/settings`. |
| **Active Model** | The currently deployed two-stage pipeline version serving live inference requests. | Displayed in the top status strip (e.g. `if-lgbm-v2.4.1`). |
| **Concept Drift** | Statistical divergence between inference telemetry and baseline training data measured via Wasserstein distance. | Warning threshold set at `0.15`. |

---

## 3. Analyst Triage & Operational Actions

| Term | Definition | Context / Rule |
|---|---|---|
| **Triage** | The structured review workflow where security analysts assess alerts, evaluate telemetry context, and assign verdicts. | Do not use "management" or "handling". |
| **Verdict** | The formal analyst determination: `True Positive`, `False Positive`, or `Escalated`. | Always use "Verdict" rather than "Disposition" or "Resolution Type". |
| **Escalate** | Transfer of an uncontained or high-severity alert to Tier 2 Incident Response for active perimeter isolation. | Action button: "Escalate Alert". |
| **Audit Trail** | The chronological, immutable operational log tracking all user authentications, model deployments, and threshold updates. | Page title: "Security Operations Audit Trail". |
| **Simulated Geo** | Explicit label applied to coordinates synthesized deterministically from non-routable private IP spaces (RFC 1918). | Must always accompany any private IP displayed on geospatial projections. |
